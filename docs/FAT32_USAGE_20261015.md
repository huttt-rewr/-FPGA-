# FAT32 图片与 WAV：拷贝文件使用说明

2026-10-15。本页对应正式顶层 `.FAT32_ENABLE(1)` 的源码。仿真/构建的实际结果见 [本轮验证](../reports/fat32_20261015/RESULT.md)。尚未进行实体卡、显示器和出声验收；以前的裸镜像 bit 不具备此功能。

## 准备卡和文件

1. 使用 **FAT32、每扇区512字节** 的 TF/microSD 卡。支持无分区表的 FAT32 卷，或 MBR 中第一个类型0B/0C的主分区；不支持 GPT、FAT12、FAT16、exFAT、NTFS。Windows 中看“属性→文件系统”确认，容量大小不能代替文件系统检查。若卡仍是以前的裸镜像布局，需要先备份有用内容，再用可信工具重新建立 FAT32 文件系统；本工程脚本不会格式化或写实体卡。
2. 在电脑上把照片转换成正高度、24位 BI_RGB BMP。支持 DIB 40/108/124，宽1～1920、高1～1080。不要额外上下翻转。已有示例在 `assets/multires_20261010`，可直接选取其中的 BMP。
3. 把 **1～4个 BMP 直接复制到卡根目录**，例如 `1.BMP`、`2.BMP`。不要放入子目录。建议英文/数字短名，文件名主体不超过8字符、扩展名3字符。FPGA跳过长名目录项，依据8.3别名的BMP扩展名识别，大小写不敏感。
4. 需要声音时，把 **一个 PCM、48000Hz、16bit、单声道 WAV** 复制到同一根目录，例如 `SOUND.WAV`。保持原有≤16MiB的解析器限制。立体声/44100Hz/浮点WAV不符合格式。
5. 安全弹出卡，插入板载TF卡座。先接好 **HDMI_B/HDMIB** 和显示器、选好输入源，再上电或按复位。

**无需 pack、无需把 `.img` 烧到卡、无需固定64MiB偏移。** 原来的镜像不是BMP/WAV文件，不应作为播放文件复制到卡里。FAT32自身可以有碎片，本版沿FAT簇链读取，不要求文件连续。

转换例子（在工程目录执行，只生成电脑上的普通文件）：

```powershell
python scripts/prepare_media.py convert photo.jpg media/1.bmp --width 800 --height 600 --fit contain
python scripts/prepare_media.py check media/1.bmp
python scripts/prepare_audio.py convert input.wav media/SOUND.wav
python scripts/prepare_audio.py check media/SOUND.wav
```

然后在资源管理器中复制 `media/1.bmp` 和 `media/SOUND.wav` 到卡根目录。音频转换所需依赖和格式限制仍见 [WAV手册](WAV_AUDIO_20261014.md)。

## 播放顺序和操作

FPGA按**根目录条目顺序**选择前4张BMP和第一个WAV，不按文件名排序。删除后重新复制会改变条目位置；`1.BMP/2.BMP`这样的名称本身不保证排序。多于4张图的其余文件不参与播放。根目录中的卷标、目录、删除项、长文件名项会跳过，遇到00目录结束项后停止；根目录也可以跨碎片簇。

KEY/SW映射保持原样，详见 [按键与拨码教程](KEY_SW_OPERATION.md)：

- KEY3短按并释放选择PLAY/BRIG/CONT；PLAY下KEY1下一张，KEY2开关自动轮播。
- KEY3长按约1.1秒打开/关闭菜单；菜单内KEY1向上、KEY2向下、KEY3短按确认。
- 声音默认静音。菜单选择AUDIO MUTE并切为OFF，使用VOLUME DOWN/UP调音量；无WAV文件时不会读不存在的音频地址。
- SW四路仍控制字幕、滚动和转场；无需串口、新开关或音频外设。显示器需具有HDMI音频播放能力才能验收出声。

枚举完成后才开始图片加载/音频请求。图片仍写入非显示帧缓存，等待完整写帧与真实帧边界确认才切换。一个BMP格式错误时不会提交半张图，可用换图操作选择下一文件。

## 新文件各自做什么

| 文件 | 职责 |
|---|---|
| `src/modules/sd/sd_fat32.v` | 解析MBR/BPB、计算卷几何、枚举根目录、保存文件大小/首簇、虚拟扇区到物理LBA映射 |
| `src/modules/bmp/bmp_read.v` | FAT32模式接收枚举数量，以文件索引调度；原BMP校验、缩放、像素输出保持 |
| `src/modules/audio/audio_wav.v` | FAT32模式输出WAV文件内相对扇区；原RIFF/fmt/data状态机、格式约束和一秒失败重试保持 |
| `src/modules/bmp/sd_card_bmp.v` | 将上述两个解析器接入FAT32，再连接原扇区仲裁器与SD栈 |
| `scripts/make_fat32_image.py` | 纯Python生成合法FAT32**仿真卡**并独立解析自检，不写实体卡 |
| `sim/tb_fat32_mount.v` | 挂载/根目录/格式错误测试和SD行为模型 |
| `sim/tb_fat32_stream.v` | 与Python原文件逐字节比对，检查碎片、边界、回环、读错、取消 |
| `sim/tb_fat32_player.v` | 使用实际播放器调度，验证两张缩放图逐像素与并发WAV循环逐样本 |

底层 `sd_card_top`、`sd_card_sec_read_write` 和 `sd_read_arbiter` 的接口与行为未更改。新层使用两个512B FAT缓存，图片/音频各一份；每流保存当前簇和簇序号，顺序前进时不从文件首簇反复查链。解析器重新读文件头或WAV回环时会回到首簇。没有实现用户随机定位接口。

为保留原有解析器回归，模块参数仍提供旧裸扇区测试方式；**正式top启用FAT32**，`SCAN_START_SECTOR/SCAN_MAX_SECTOR/AUDIO_START_SECTOR`不参与正式文件地址计算。旧工具的pack命令仅供历史测试，不是当前制卡流程。

## 错误与排查

新层会拒绝坏引导签名、非512字节扇区、非法簇大小、非FAT32卷几何、越界文件索引/扇区、坏簇、保留簇、文件长度尚未结束却提前链尾和短SD扇区。根目录遍历上限默认4096簇，损坏的目录循环不会无限读卡。图片取消会排空当前物理事务，避免截断音频或把旧返回当成新请求。

挂载失败保持错误状态，修正卡后按整机复位重新挂载。原状态数码管显示9（卷格式/几何）、A（挂载SD读错/长度错）、b（根目录簇链损坏）、C（根目录遍历上限）；内部 `mount_error_code` 分别为1～4。未增加顶层管脚、OSD端口或70位状态总线字段。图片加载读错走原LOAD错误保护；WAV读取失败仍走原音频错误/延时重试。

无图时先检查：确实FAT32、根目录有BMP、扩展名与格式符合要求、使用的是本版重新构建的配置。无声时再检查：根目录有WAV、格式48000/16bit/mono、板载菜单解除静音、显示器音量和音频能力。卡内容变化需要复位重新枚举；不支持运行中热插拔重扫。

## 在ModelSim里复现

```powershell
python scripts/make_fat32_image.py fixtures
python scripts/make_fat32_image.py verify reports/fat32_20261015/vectors/super.img
python scripts/make_fat32_image.py verify reports/fat32_20261015/vectors/mbr.img
python scripts/static_check.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_tests.ps1
python scripts/run_build.py
```

只运行三个 FAT32 专项可用 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_fat32_tests.ps1`。它与全量回归共享仿真镜像目录，请依次运行，避免同时重新生成正在读取的镜像。

仿真模型按LBA从镜像读真实512字节，不用硬编码假BPB代替文件。测试镜像包含两个FAT、FSInfo/备份引导扇区、跨簇根目录和故意打散的数据簇；Python `verify`重新解析链并核验文件SHA。镜像只用于仿真，完整回归脚本会自动生成。综合/布局布线与时序是否通过必须看本轮报告，不能用历史余量代替，也不能把内部复位removal说成HDMI管脚hold。
