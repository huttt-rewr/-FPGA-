# 动态字幕与图片转场使用说明

> 本文记录10月9日版本。10月10日当前工程已增加可变尺寸缩放、B1操作项选择和亮度/对比度OSD；亮度不再固定，旧bit不包含新功能。请使用 [缩放与亮度/对比度详细手册](SCALING_AND_PICTURE_CONTROLS_20261010.md) 中的当前操作说明，最终bit见 [构建状态](BUILD_STATUS.md)。

本次实现用户要求的“图层叠加与字幕效果”和“图片切换与转场特效”。HDMI仍固定640×480，板上连接仍用HDMI_B；图片缩放适配不属于本次实现范围。

## 1. 下载本版后能看到什么

- 左上角：原有播放、图片、加载、EDID、音量状态。
- 右上角：`UP HH:MM:SS`，表示FPGA复位后运行时间；不是当前日期/北京时间，99:59:59后循环。
- 底部：半透明蓝色字幕条，黄色标语每帧移动1像素，从右向左循环。默认约59.5像素/秒。
- 换图：选择淡出淡入模式后，旧图片逐渐变暗，换到新图后逐渐变亮。首图直接显示，不对不存在的旧图做转场。

半透明字幕使用每通道近似50%背景和50%蓝色底条混合，文字覆盖在其上。原有状态面板最后叠加，优先级最高。字幕和时间不随图片一起淡出/滑动，因此在换图期间仍可阅读。

## 2. 当前通过SW与按键操作

### 1. 先认清四路拨码

依据官方 `J:/DEMO/6_cnt10/cnt10.adc` 第21～24行，`8_key_sw/key_sw.adc` 使用相同四路输入。下面“第1～4路”按代码 sw[0]～sw[3] 定义，不保证是实物从左到右。板上印的是1～4还是0～3、ON方向和实际板卡版本仍需上板核对。

| 本手册编号 | 顶层信号 | FPGA管脚 | 功能 |
|---|---|---|---|
| 第1路 | sw[0] | C8 | ON：显示字幕条和右上运行时间；OFF：隐藏两者 |
| 第2路 | sw[1] | C7 | ON：标语向左滚动；OFF：停在当前位置 |
| 第3路 | sw[2] | C6 | 转场选择的低位，与第4路组合 |
| 第4路 | sw[3] | C5 | 转场选择的高位，与第3路组合 |

代码默认闭合到GND为ON，即低电平有效；断开时由上拉读取为OFF。官方例程确认了引脚与上拉，但没有完整板卡原理图证明你实物的ON丝印方向。若操作结果正好反向，先核对原理图或测量；正确修正点是 `switch_controls.v` 的 `ON_LEVEL` 参数，不要猜其他引脚。它支持逐位指定ON电平。

### 2. 转场怎么选

| 第3路 | 第4路 | 所选效果 | 字幕顶边颜色 |
|---|---|---|---|
| OFF | OFF | 直接切换 | 白色 |
| ON | OFF | 旧图淡出 → 黑场换图 → 新图淡入 | 橙色 |
| OFF | ON | 旧图右滑出 → 黑场换图 → 新图从右侧滑入 | 青色 |
| ON | ON | 淡出淡入与滑动交替，每次实际启动转场换一种 | 紫色 |

首张图片直接显示。交替模式复位后第一次动画是淡出淡入，下一次滑动；首图不消耗轮次。退出交替模式再回来保留轮次，整机复位才重置。选择模式不自动换图，要按下一张或启用自动播放才能看到动画。

转场开始时锁定模式。动画进行中改变拨码，当前动画继续完成，新选择用于下一次转场。第3、4路一起改时，先拨好、等至少约20ms稳定，再按换图；若自动播放正在运行，建议先暂停，防止在两次拨动之间启动中间模式。

### 3. 两个按键怎么用

| 按键（代码名） | FPGA管脚 | 操作 |
|---|---|---|
| key1 | B2 | 按一下下一张，最后一张之后回到第一张 |
| key2 | C1 | 按一下自动播放开/关，观察左上 PLAY ON/OFF；至少需要两张图片 |
| rst_n | A2 | 整机复位，重新初始化SD、扫描图片，运行时间归零 |

丝印名称不一定与代码key1/key2相同，以B2/C1对应的板载按键为准。按键保持超过约50ms后松开；长按不会连续翻页，也没有长按菜单。等待LOAD忙状态结束再按下一次，忙时不会排入无限个请求。

### 4. 一次完整演示

1. 使用 [接线与制卡教程](CONNECTION_AND_USAGE.md) 准备至少两张640×480、24位BMP的原始扇区镜像。普通复制文件不是本工程的可靠制卡方式。
2. 断电插卡，HDMI_B接显示器，选择对应HDMI输入，连接电源和下载器。
3. 第1、2、3路设ON，第4路设OFF：这表示字幕显示、文字滚动、淡出淡入。
4. 下载本页链接的SW版bit，必要时按A2对应复位键。等待初始化、扫描和首张图显示。
5. 观察底部半透明蓝条、黄色英文标语、右上 `UP HH:MM:SS`。UP是复位后的运行时间，不是北京时间。
6. 第2路拨OFF：标语停止；再拨ON：从当前位置继续。隐藏期间滚动位置也停止，恢复后继续。
7. 第1路拨OFF：字幕和时间隐藏，左上状态仍显示；拨ON恢复。只拨第2路不会关闭字幕。
8. 按B2对应按键：加载新图完成后，旧图淡出、新图淡入，全程约1.1秒，读卡等待另计。
9. 第3路OFF、第4路ON，再按下一张：观察滑动。
10. 第3、4路均ON，连续换两次图片：依次观察淡出淡入和滑动。按C1对应按键可自动轮播，再按一次停止。

三条内置英文标语随图片序号选择：第1张WELCOME、第2张LEARN、第3张ENJOY、第4张回WELCOME。当前索引是控制端选择状态，可能在图片正式显示前变化；标语不是图片文件名。更换标语时滚动从起点开始。不支持任意文字输入或中文字库。



第1/2路字幕与滚动；第3/4路组合选模式。旧e/c/r/g/n/b/p串口命令在当前顶层已禁用。

## 3. 实现与操作边界

完整硬件依据和原理见 [SW手册](SW_CONTROLS_20261009.md)。亮度固定0、状态OSD常开、测试图关闭、音频静音；预置标语随图片序号选择。

## 4. 两种转场具体怎样实现

**淡出淡入**：旧图亮度系数从31/32逐帧降低到0，完全遮黑后在场消隐切换SDRAM缓冲，新图系数从1/32逐帧升到1。RGB直接做定点比例缩放，属于RGB码值空间的渐变，未做Gamma校正。

**滑动**：每帧平移20像素，经过32步移出640像素宽度。输出坐标x读取同一行的`x-offset`像素，不存在的左侧区域补黑；新图在遮黑状态切入后，偏移从640逐帧降低到0。旧图向右移出，新图从右边移回正常位置，不是左右两图同时拼接推屏。

两种转场都经过黑场交接，约65个帧间隔完成（当前帧率下约1.1秒）。图片层遮黑期间HDMI像素和行时序仍连续，字幕仍显示；不会暂停像素时钟或省略被遮盖像素。

当前SDRAM读取通路一次提供一帧像素，未增加双图同时读取。因此本版没有实现旧图/新图交叉溶解，也没有实现两幅图同时占据左右半屏的推屏。这两种效果需要重新设计双路读取、带宽和缓冲所有权，不能仅改透明度参数得到。

## 5. 源文件与数据通路

```text
SDRAM像素 / 测试图
        ↓
video_enhance：原有亮度
        ↓
transition_pixels：淡出比例 / 行缓存平移（固定2拍）
        ↓
caption_overlay：半透明底条、运行时间、滚动标语（固定1拍）
        ↓
status_osd：原有状态面板
        ↓
video_rgb_to_axis_640x480 → 官方HDMI核 → HDMI_B
```

| 文件 | 改动与职责 |
|---|---|
| [switch_controls.v](../src/modules/control/switch_controls.v) | 四位同步、整体消抖，提供字幕/滚动/模式电平 |
| [player_control.v](../src/modules/control/player_control.v) | 保留历史命令解析及回归，当前top不实例化 |
| [frame_swap.v](../src/modules/video/frame_swap.v) | 可选转场状态机；锁定目标缓冲和模式，完全遮黑时切换，入场完成才返回ack |
| [video_coordinates.v](../src/modules/video/video_coordinates.v) | 生成与当前输入像素对应的x/y；用于源图和字幕，不把流水线后的坐标反馈给前级 |
| [transition_pixels.v](../src/modules/video/transition_pixels.v) | 1024×24同步行缓存、右移裁剪、逐通道亮度比例；零偏移旁路避免同地址读写依赖 |
| [caption_overlay.v](../src/modules/osd/caption_overlay.v) | BCD运行计时、帧边界快照、逐像素滚动、50%混色和字模叠加 |
| [top.v](../src/top.v) | 控制快照扩为30位，接入新像素流水线，同步延迟VS/DE，新增四路SW外部端口 |

行缓存仅存短期像素，不是新增整帧缓存。内存不做全阵列复位，滑动只读本行已经写入的位置；偏移0直接旁路，偏移640整行遮黑，避免显示旧行内容。转场期间控制端保持忙，新旧帧缓冲都保留到确认。

内置字库支持大写ASCII与数字，当前三条标语为英文。当前按图片序号选择预置标语，没有实现任意串口字符串上传或中文字库。需要修改内容可编辑`caption_overlay.v`的40字符标语表，再重新构建；字符不足会影响对齐，超长会截断。时间没有RTC/NTP来源。
