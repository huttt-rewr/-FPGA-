## 任务1 → 保持时间 → src/constraints/timing.sdc

### 修改代码及插入位置
本次没有加入输出延时或修改 C1 相位。保留现有实际时钟定义：
```tcl
create_clock -name clk -period 20 -waveform {0 10} [get_ports {clk}]
derive_clocks
```
原理说明：报告 +0.011 ns 是 HDMI 加密核内部复位释放 removal 检查，不是 TMDS 管脚 hold，增加 PAD 输出延时不能改善这条内部路径。

原始最差起点：`u_hdmi_1_4b_transmitter_core_wrapper/u0_reset_sync/O_sync_reset_reg_syn_70.clk`；终点：`u_hdmi_1_4b_transmitter_core_wrapper/u_hdmi_tx_controller_wrapper/u_hdmi_island_data_assemble/S_CH0_D2_shift_reg[25]_syn_4.sr`。

TD 实测拒绝 `set_property OUTPUT_DELAY 2`（USR-7001），并拒绝当前 IOBE/LVDS33_E 输出上的 `OUTDELAY=2`（USR-8409）。不能伪造满足该组合的可复制约束。即使按用户提供的步长简单相加，0.011+0.200+0.150=0.361 ns，也未达到 0.5 ns；实际时序更不能这样直接相加。

`src/constraints/timing.sdc` 是 read_sdc 读取的时序文件，不改名伪装成物理 ADC。没有新增任何时序屏蔽。原工程对异步 UART/IR/按键输入的首级同步边界例外保留，未用于 HDMI 或 SDRAM 目标路径。

`src/ip/pll/video_pll.v` 的参数仍为：
```verilog
.CLKC1_DIV(8),
.CLKC1_CPHASE(7),
.CLKC1_FPHASE(0)
```
原理说明：保持像素/串行时钟的既有关系；在 1 GHz VCO 下官方模型细相位步长为 125 ps，不能声称参数一步等于 150 ps。输入控制引脚延时也未随意减少，因为它与当前内部最差路径无直接关系。

可选试验脚本 `scripts/experiment_hdmi_reset_margin.tcl` 对真实复位路径施加额外保持裕量并调用 TD `fix_hold`，输出单独 trial 数据库。一次试验全局 HWNS 为 +0.038 ns，仍未达到目标；未替换正式数据库。全局 0.55 ns 裕量试验出现大量违例，被排除。后续需针对加密 HDMI 核复位复制网络逐路径优化，或向 IP 提供方获取可支持的复位方案。

## 任务2 → HDMI 伪差分 → src/constraints/pin.adc

### 修改代码（替换原四条 HDMI 输出约束，已应用）
```tcl
set_pin_assignment { HDMI_CLK_P } { LOCATION = C3; IOSTANDARD = LVDS33_E; DRIVESTRENGTH = 8; PULLTYPE = NONE; }
set_pin_assignment { HDMI_D0_P } { LOCATION = G5; IOSTANDARD = LVDS33_E; DRIVESTRENGTH = 8; PULLTYPE = NONE; }
set_pin_assignment { HDMI_D1_P } { LOCATION = F1; IOSTANDARD = LVDS33_E; DRIVESTRENGTH = 8; PULLTYPE = NONE; }
set_pin_assignment { HDMI_D2_P } { LOCATION = E1; IOSTANDARD = LVDS33_E; DRIVESTRENGTH = 8; PULLTYPE = NONE; }
```
原理说明：使用 TD 实际接受的伪差分标准和驱动属性，负端由工具自动产生，不创建不存在的顶层 N 端口。

| 信号 | P | N（自动配对） | 外部 BANK | 最终报告 |
|---|---|---|---|---|---|
| 时钟 | C3 | C2 | 3 | LVDS33_E / 8 mA |
| 数据0 | G5 | G6 | 3 | LVDS33_E / 8 mA |
| 数据1 | F1 | F2 | 3 | LVDS33_E / 8 mA |
| 数据2 | E1 | D1 | 3 | LVDS33_E / 8 mA |

证据：`reports/physical_area.txt` 同时列出了8个物理端口。不是把4个负端遗漏了。顶层及 `src/modules/hdmi/lane_lvds_10_1.v` 不需要新增差分输出原语；保留现有 EG_LOGIC_ODDR 和 TD 差分推导。

TD 6.2 的 set_property 命令存在，但对这些端口 IO 属性的用法报错；不能把命令存在当作属性可用。官方手册实际名称是 IOSTANDARD、DRIVESTRENGTH、OutDelay、DiffResistor；DiffResistor 是差分输入属性，对该输出设置 NONE 也会报错，因此不添加 TERMINATION 或 DIFFRESISTOR 输出约束。

### 板级连接（仅说明待核对网络，不是已确认 HDMI 改板方案）
用户给出的3R网络拓扑可以表述为：P引脚串联 Rs 到 P线，N引脚串联 Rs 到 N线，Rp 跨接在两个串联电阻之后的 P/N 线上。150Ω/150Ω/140Ω 仅作为用户提供的待验证参数，不作为本工程官方推荐值或装配指令。它不能仅凭差分幅度就判定兼容 TMDS；还必须核对接收端两路到3.3V的终端、共模、输出高低电平、电流、眼图和板上原有网络。没有 HX4S20C 原理图前，不应再叠加电阻或直接认定483mV满足接口。

## 任务3 → PLL 内部反馈 → src/ip/pll/sys_pll.v、video_pll.v

### 修改代码（两个 EG_PHY_PLL 参数块和端口块，已应用）
```verilog
.FEEDBK_MODE("NOCOMP"),
.FEEDBK_PATH("VCO_PHASE_0"),
.REFCLK_DIV(1),
.FBCLK_DIV(20),
// Other output divisors and phases are unchanged.
```
在同一实例端口列表中：
```verilog
.fbclk(),
```
原理说明：内部 VCO 自反馈不走外部补偿网络；50MHz×20/1=1000MHz，输出分频10/25/25和40/8分别保持100/40/40MHz与25/125MHz。未使用的反馈端悬空消除无实际可布连接的警告。

已同步 VHDL 模板的反馈/分频参数和 extlock 接口；VHDL 非当前编译源，未完成 VHDL 编译。IPC 的模式/倍频/分频字段同步为 No Compensation /20/1，但其导入再生成尚未验证。所有文件明确标记为核查后的手工补丁，不能冒充 TD IP 向导重新生成的文件。模拟环路参数保留原值，仍需用 TD 6.2 的 EG4S20 向导复核环路设置和实际锁定。

用官方 EG4 仿真库新增 `tb_pll_clocks`，验证两路锁定及五路输出周期；它不验证硬件抖动、环路稳定性或板级相位。

### 警告说明（可用于工程说明）
- USR-6135 两路 PLL 外部反馈补偿警告：本次最终实现日志中已消失。
- PHY-5014 未使用反馈端连接警告：最终采用未连接反馈端后已消失。
- PHY-7002 SDRAM 位置未满足：仍有两条，不能无依据归类为无害；需向安路确认合封器件模型位置与最终映射。
- PHY-5079 局部时钟布线：仍有一条，报告定位到系统 PLL C2 → U3/u2_ram/SDRAM_CLK，不能与已消除的 PLL 反馈警告混为一谈。
- SD/DDC/TMDS 外部 IO delay 未签核，内部 STA 正值不等于 HDMI 接收端时序通过。

## 验证操作步骤

1. TD 6.2.168116 打开根目录 video_improve.al，确认 top 和 EG4S20BG256；核实实物 I7 与工具 Speed=NA 的对应关系。
2. 执行 `python scripts/static_check.py` 检查44个源、31位逻辑 IO 与两个工程入口一致性。
3. 执行 `powershell -File scripts/run_tests.ps1`，12项必须全部通过；执行 `powershell -File scripts/run_pll_test.ps1`，PLL测试必须通过。
4. 执行 `J:/Anlogic/td.6.2.1/bin/td_commands_prompt.exe E:/fpga/scripts/synth.tcl`，检查 synthesis.log，不能只看进程退出码或 COMPLETED。
5. 执行相同工具加 `E:/fpga/scripts/implement.tcl`，重新 place、route、update_timing -mode final；检查 ERROR、CRITICAL-WARNING、未约束路径、SWNS/STNS/HWNS/HTNS及IO物理报告。
6. 本次最终候选：SWNS +1.090ns、STNS 0、HWNS +0.011ns、HTNS 0；尚未达到≥+0.5ns。不能把报告全局HWNS标成已签核的HDMI管脚保持余量。
7. 原 reports/video_improve.bit 是历史候选；本次不生成新bit。只有补齐板级参数并复核网络、时钟和约束后，才考虑生成并测试彩条、单张BMP、异常恢复和8小时运行。
