# FAT32 范围比较优化与验证

本轮在 `a5d76ca` 基础上，先核验工作区已有的一行改写，再独立验证另一个组合等价候选。最终采用的版本以[本轮冻结报告](../reports/fat32_compare_20261018/RESULT.md)为准；功能回归通过不能代替布线后 STA。

最终选择原则：两个可合法路由的比较改写分别得到 SWNS −0.743ns、−0.936ns，均劣于原基线 −0.592ns；第三个组合分段候选出现 PHY-8023 局部布线冲突。因此撤回本轮三处 RTL 候选，恢复 `a5d76ca` 的 FAT32 原表达式，保留新增单测及完整试验记录。用户初始的一行改动保存在 `reports/fat32_compare_20261018/initial/` 和提交 `a772d06`，没有遗失。恢复版另行执行新鲜构建和 94 项回归，不沿用旧报告作为本轮验收。

## 改动的作用

`sd_fat32` 将 BMP/WAV 的文件内扇区请求映射为卷内物理扇区。读取之前，`STREAM_CHECK` 验证文件存在、文件非空、请求没有越过文件末尾、目标簇合法。优化的是其中“文件内扇区号是否越界”的组合判断，状态、握手、寄存器数量和字节流均不因此改变。

原式：

```verilog
{1'b0,request_rel} >= request_sectors
```

改写：

```verilog
(|request_rel[31:24]) ||
(request_rel[23:0] >= request_sectors[23:0])
```

`request_size` 是 32 位字节数，`request_sectors` 仍保留原来的 33 位声明和计算：

```verilog
request_sectors <= {10'd0,request_size[31:9]} + (|request_size[8:0]);
```

最大值为 `ceil(0xffffffff/512)=0x800000=2^23`，所以 `[32:24]` 恒为零。若请求高八位有任一位为 1，请求至少为 `2^24`，一定越界；否则只比较双方低 24 位即可。此证明涵盖任意 32 位请求，不要求请求本身只有 24 位。最大文件计算产生的 bit23 进位得到保留。

这是二态、已初始化输入下的等价关系；测试没有把未知值 X 当成可读文件地址。综合器可能已自动消除部分常零位，因此源码位宽变短不保证实际电路或时序必然改善。

## 怎样复现仿真

在工程目录运行：

```powershell
python scripts/static_check.py
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run_tests.ps1
python scripts/run_build.py
```

新增 `sim/tb_fat32_compare.v` 已通过 `$mergeTests` 同时登记到编译和执行列表。它直接实例化正式 `sd_fat32`，白盒设置范围检查前置状态，执行真实 `STREAM_LIMIT` 计算及 `STREAM_CHECK` 寄存结果。测试参考式保留原 33 位比较和全部其他错误条件，不复制优化式作为预期结果。

- 文件大小覆盖 0、1、511、512、513、接近 4 GiB 的整扇区和非整扇区、`0xffffffff`。
- 请求覆盖 0、`2^23-1`、`2^23`、`2^24`、`2^31-1`、`0xffffffff` 及其他高位边界。
- 检查零文件、文件不存在、目标簇越界、簇 0/1、簇超上限、音频与图片所有者。
- 随机请求以及每个随机文件末扇区/越界首扇区验证，确认检查阶段不占用 SD 通道。

白盒单测只验证比较逻辑；真实挂载、FAT 链、MBR、图片/音频、SD 卡协议及缩放行为依靠原有完整回归，不能用它代替上板测试。

## 没有采用的进一步截断

`data_clusters` 与 `max_cluster` 描述整个卷，不能从单个文件的 32 位大小推出它们最多 24 位。`working_cluster<2` 若改成按位判定，必须检查全部高位为零，单看最低两位会误判较大簇号。没有充分证明和独立验证时保留原实现。

第二轮针对真实报告中 `data_clusters` → `stream_bad` 的 −0.375ns 路径，尝试的判断是：

```verilog
// target_index 为 24 位，data_clusters 保持 32 位。
!(|data_clusters[31:24]) && target_index >= data_clusters[23:0]
```

这是对任意 32 位 `data_clusters` 都成立的代数改写：若卷簇数高八位非零，它必然大于任意 24 位目标簇序号，原 `>=` 结果为假；高八位为零时，比较低 24 位即可。它没有截断卷容量。新增隔离测试覆盖卷簇数 `0x01000000`、`0xffffffff`、`0x00ffffff`、0、`0x00800000`，让其他错误条件为假，避免范围比较被其他错误遮蔽。该候选必须独立完成回归和物理实现，是否采用取决于实际 STA。

第三轮针对第二轮实测最差 `next_cluster` → `cluster_ok` 的 −0.936ns 路径，尝试将完整 32 位 `next_cluster<=max_cluster` 写成：

```verilog
next_cluster[31:16] < max_cluster[31:16] ||
(next_cluster[31:16] == max_cluster[31:16] &&
 next_cluster[15:0] <= max_cluster[15:0])
```

这利用无符号数高位优先比较的恒等式，不假设卷或簇号只有 24 位，不增加寄存器。簇号至少为 2、必须小于 `0x0ffffff0` 的原检查均保留。实际 `FAT_VALIDATE` 单测包括 16 位进位边界、保留/坏簇/EOC 边界、高位非法簇、最大值及随机 28 位候选；与其他范围测试合计 4,074 个真实 DUT 用例。第二轮路径报告有 8 级 LUT、10.656ns 数据路径延迟，其中 7.249ns 为布线；组合重写只可能改变电路映射，不能保证高密度布局中的线延迟改善，仍以独立物理实现为准。

## 实现和板级边界

不修改 HDMI 加密核、PLL/SDRAM 相位、引脚约束、70 位状态总线或视频同步；保留双线性、全部 OSD/字幕/特效/游戏、音频及两种输出模式。模式请求 0/1 都输出 VGA，2 在 EDID 支持时输出 SVGA，并非三种输出分辨率。

SDRAM 的 PHY-7002 两条及 PHY-5079 一条仍须厂商确认，详见[待办](BOARD_PENDING.md)。不能通过删除硬宏或绕开真实时序路径来消除问题。仅在新鲜布线数据库的全部时序指标非负且核对警告后才允许生成本轮 bit。内部复位 removal 不是 HDMI 管脚 hold，也没有整体 +0.5ns 验收声明。实板下载、写实体卡、出图/出声及吞吐实测未在本轮执行。
