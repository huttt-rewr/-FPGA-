# 静止图片撕裂与白条：修复、验证和上板判别

2026-10-13。板上已观察到**停在单张图片时也有撕裂、小白条**。这使持续显示链路成为优先调查对象；切图特效不能解释所有现象。本文记录代码中可复现的缺陷和本机修复，不把仿真或 STA 当作上板已修复。

## 数据流及实际改动

`SD SPI → CMD17 扇区+CRC16 → BMP 头扫描/缩放 → 写 FIFO → SDRAM 备用完整帧 → 场消隐提交 → SDRAM 显示帧 → 读 FIFO → OSD/字幕 → HDMI IP/TMDS → HDMI_B`。

1. **刷新配置错误。** `global_def.v` 的宏展开原为 `64000000/1000000000/40000000/2**11`，Verilog 整数除法从左向右计算，第一步已变成 0。官方 `sdr_init_ref` 可读计数器用此值产生刷新请求。修正为带括号的时钟周期和刷新间隔后，在 40MHz 下宏值为 1249（计数器含0端点），每1250拍即31.25µs一次请求；避免仅加括号后1251拍的边界偏差。六份配置头同步更新；`src/ip` 中官方受保护源字节未修改。修改前测试记录为 0 次请求，修改后本次测试窗口内记录 4 次。旧 ModelSim 无法编译官方加密尾部，测试仅抽取官方**可读刷新计数器**；它不覆盖 SDRAM 命令尾部、真实内存保留时间或板上电气。
2. **读事务排空错误。** 旧控制器在最后读命令后固定等 10 个内存时钟就释放共享端口；这只是假定延迟，不保证最后一个读数据实际到达。现在逐突发数已发请求和 `Sdr_rd_en` 返回，全部返回才允许下一突发、写入或新帧清空读 FIFO。刷新标志期间不发新命令；发起突发前检查初始化、刷新及 busy。这个请求/返回计数依赖官方接口“每个请求恰好返回一个数据字”，真实硬核仍需实板验证。
3. **显示优先级。** 800×600 的 40MHz 像素有效区需要 160MB/s，等于 40MHz×32bit 理论峰值；读写、刷新及行消隐必须严格调度。本轮曾尝试 `wrusedw<192` 才阻止后台写，带刷新/延迟的多帧压力测试在像素索引 1536 处欠载。自适应模式门槛提高到 384 个已缓存像素后，三帧/144万像素、后台 64000 字写入、每 1250 周期暂停 22 拍及突发返回起始延迟 10/17 拍的行为模型通过。**这个测试不是加密 SDRAM 核的实测带宽证明。**
4. **欠载可见且按帧恢复。** 读 FIFO 空时不继续取垃圾像素，该帧余下部分使用安全底色；下一帧请求在返回数据排空后清 FIFO 重新读取。粘性欠载/写溢出接入状态 OSD 的 `LOAD:E` 错误指示，避免“错误被颜色调整/特效掩盖”。首张图正式提交前不消费视频 FIFO，避免冷启动误报。若实板仍显示 `E`，可结合何时出现判断读 FIFO 或卡载入错误，复位前拍照记录。
5. **读卡完整性。** SD SPI CMD17 每 512 字节后带两个 CRC16 字节；旧实现无条件接受，当前逐字节计算 CRC16-CCITT（多项式 `0x1021`、初值 0），只在匹配时发扇区成功脉冲。单比特错误走已有传输失败路径，当前显示缓冲区不提交坏图；修正了命令发送尚未满 6 字节时误把响应值当作 R1 的条件。注意：缩放器只有收到完整扇区成功脉冲才把扇区缓存标为有效。

## 双缓冲、OSD、混合与音频的边界

与修复相关的100MHz控制路径也作了流水切分：BMP文件扇区数先寄存后加扫描地址；缩放器先验证尺寸/锁存宽高比，再配置除法器，并在行开始锁存相邻源行地址；BMP头部输入把字节与索引一起寄存，原始扇区计数不延后，保持紧邻末字节的结束握手；SD等待超时提前一拍预判并寄存，避免大比较器与状态译码串联驱动片选。缩放状态机改为24位独热编码，缩短寄存器使能的多级状态译码。每次变更均重新用实际布局布线报告判断，不能把某条路径改善当作整个设计已通过。

本工程已经有两个 SDRAM 整帧区和场消隐换帧，并非本次重新设计。已有切图效果以**逐帧 0–32 权重**淡出至黑、换帧、再淡入；它不是同时读取两张完整帧的交叉溶解。800×600 的当前链路在有效区已达理论峰值，直接双读再做 Alpha 混合至少需要 320MB/s 原始读带宽，会扩大欠载风险，因此本轮没有把它误称为已实现。OSD 状态板和字幕背景已经使用 1/2 Alpha 混合、字模 ROM；亮度、对比度、字幕/转场参数在帧边界锁存，KEY/SW 控制保留。可选的色彩 LUT 尚未加入；应先做实板校准与资源评估，再选择分段 LUT/每通道 BRAM。SD 音频→PCM→I²S发送→外置 DAC 和 PCM→FFT→OSD 频谱需要外接音频硬件/共享 SD 调度；用户已选择本阶段**先修画面和读卡，音频暂不接硬件**，故没有虚构 DAC 接线、FFT 结果或音频功能。

## 上板顺序

1. 保留原卡镜像和旧 bit；新源码必须经过新综合/布局布线/bitgen，**不能复用** `video_improve_adaptive.bit` 断言已经修复。
2. HDMI_B 连接显示器，固定一张高对比度测试 BMP。KEY3选到`MODE:PLAY`，若`PLAY:ON`则按KEY2切到OFF；SW第3、4路选逻辑00关闭转场（实物ON方向按板卡核对），SW第1路可关闭字幕以便观察。停止操作后观察至少30分钟，记录白条位置是固定还是移动、是否周期复现，以及`LOAD:E`是否亮起。31.25µs的刷新周期只能用仪器/内部抓取测量，不能凭肉眼认定。
3. 再轮播两图，确认换帧只在场消隐；之后做反复断电/重插卡、坏卡和长时间保留测试。若依然在单张图出现小白条，优先抓 `Sdr_rd_en`、读 FIFO 占用/empty、刷新/busy、视频 DE 与 TMDS 眼图，核查 SDRAM PLL 相位及 PHY-7002/5079。仅靠行为模型和 STA 正余量不能排除硬核采样/板级信号完整性问题。
