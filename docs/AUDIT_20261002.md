## 2. IO 约束核查

原有 UART RX=F12、TX=D12、IR=D14 各重复 3 次，内容相同；这是重复定义，不是不同信号短接同一引脚。已删除 6 条重复项，每个逻辑 IO 保留一条。

基础映射对照本机 `J:\lab_ex4_tf\src\user_source\constraints_source\pin.adc`；UART 对照 `J:\DEMO\16_uart_rs232\uart_test.adc`。IR D14 是可选外接输入，仍需确认实际板上接线。

TD `physical_area.txt` 确认差分输出自动占用：

| 通道 | P 管脚 | 自动 N 管脚 |
|---|---|---|
| HDMI 时钟 | C3 | C2 |
| HDMI D0 | G5 | G6 |
| HDMI D1 | F1 | F2 |
| HDMI D2 | E1 | D1 |

因此顶层只写 P 输出并不等于漏了 N 约束。用户 IO 共 31 位、用户 PAD 共 35 个。SDRAM 使用 `EG_PHY_SDRAM_2M_32`，由器件模型建立专用连接与时序，不能把它误当成顶层漏接的普通 SDRAM GPIO。

用户先前提供的金山链接未取得可用板级原理图；芯片手册不能证明开发板接线。这里核实的是参考设计、当前 RTL 与 TD 映射的一致性。

## 4. 时钟与带宽取舍

| 时钟 | 本次频率 | 用途 |
|---|---:|---|
| clk | 50 MHz | 板级参考 |
| sys PLL C0 | 100 MHz | SD SPI、UART、NEC、控制、数码管 |
| sys PLL C1 | 40 MHz | SDRAM 用户逻辑 |
| sys PLL C2 | 40 MHz，相移约 187° | SDRAM 时钟输出 |
| video PLL C0 | 25 MHz | 640×480 光栅/OSD/HDMI 像素 |
| video PLL C1 | 125 MHz | TMDS 串行 |

40 MHz×32-bit 的理论接口带宽为 160 MB/s；显示平均读需求约 73.14 MB/s、有效像素期间约 100 MB/s，SD SPI 理论原始字节速率最高约 3.125 MB/s。理论预算容纳本次图片播放，但刷新、页切换、仲裁和硬核开销尚未通过板上吞吐压力测试。没有宣称支持 1080p60 或 60fps 文件视频。

## 6. 仍存在的限制和下一步

1. **板级信息不足**：引脚对照参考工程，不是对用户板的原理图签核；IR 需外接接收头，LVDS33/TMDS 电阻网络与电压需核实。
2. **外部时序不完整**：SD/DDC 缺实际器件/板线路延迟；check_timing 仍提示 input/output delay 和硬宏相关提示，详见 BOARD_TIMING.md。
3. **厂商警告未全部消失**：SDRAM 硬宏位置调整、局部时钟布线、PLL feedback compensation、加密 IP 宽度/悬空提示均有保留。最终 no-clock 和组合环检查为 0，不能因此忽略其他警告。
4. **SD 支持有限**：不是 FAT32；文件头必须在扫描范围内且扇区对齐、内容连续。旧 SD v1/MMC、扫描/初始化无限等待、底层写卡数据响应与所有坏卡情况未完整处理。主工程写卡使能固定 0。
5. **视频与 UART 缓存有界**：64 像素/16 字节，持续超额负载仍会溢出；错误标志可见，不再声称无限无丢失。
6. **存储仲裁仍沿用参考 IP**：固定 burst、刷新/忙握手、非 256 整倍数帧长未重新设计。当前固定帧长 307200 是整倍数，新增测试只覆盖这条受支持路径。FIFO full 不会增加可用吞吐量，极端阻塞仍可能丢新输入。
7. **没有实板验证**：还需彩条/单图、重复换图、坏图恢复、多卡与多显示器、音频、长时间压力测试。候选 bit 文件只是构建产物，本次没有向板卡烧录。

本报告把已修复、误判和待验证项分别说明，不把“无综合语法错误”写成“工程所有问题已经消失”。
