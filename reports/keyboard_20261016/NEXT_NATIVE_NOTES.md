# 后续原生SD实现边界

此文件是实现备忘，不能作为完成证明。阶段三/四未验收前不安装原生SD。

公开Linux驱动已独立核对CMD6状态：`linux_sd_reference.c`中361行检查status[13]高速支持位，406行检查status[16]低四位是否选中High Speed。参考来自https://github.com/torvalds/linux/blob/master/drivers/mmc/core/sd.c，本地保存只作协议依据，不纳入FPGA编译。

50MHz不能继续照用25MHz的原始边沿采样预算。卡从下降沿更新，50MHz半周期只有10ns；卡输出延迟与PCB往返延迟可能超过它。可在100MHz域延后一个周期采样，使读取点接近下一次下降沿，但必须配合外部输入最小/最大延迟、SD_CLK输出延迟和实测裕量核查；不能凭零延迟模型签核。

高速与工作时钟标志需分开：旧high_speed变量只代表退出识别频率、进入25MHz，不代表CMD6已协商50MHz。ACMD6只负责四位宽度，普通CMD6负责高速功能切换。四位25MHz必须先完成整机验证。

PHY要支持64字节CMD6数据块和512字节扇区，两者均完整校验四条CRC16。查询不支持或忙时保持25MHz；切换状态CRC损坏或超时则禁用本轮高速尝试并重新初始化，避免主机和卡对模式判断不一致。成功查询/切换/拒绝/CRC损坏/缺失数据都需要独立卡模型测试。

不修改FAT32、图片/音频解析算法、仲裁语义；正式顶层六线接线和约束同步。保留SPI回归profile以验证既有功能，正式native profile不能退回SPI。没有下载实体板或写实体卡的授权执行记录，必须将协议仿真、内部STA和实体卡吞吐分开报告。
