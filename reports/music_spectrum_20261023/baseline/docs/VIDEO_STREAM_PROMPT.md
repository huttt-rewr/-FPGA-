# 视频播放（原始帧流）· 提示词 · 从"图片播放"到"能动的画面"

> 用途：把本文件整段交给 GPT/协作者执行。目标：让系统能**连续播放帧序列**（≈ 简易视频），
> 从"换图节拍幻灯片"升级成"24fps 画面流"。
> **必须适配本工程**：安路 EG4S20、TD 6.2.1、复位高有效、整数运算；SD 已上 4 位 50MHz（CMD6）。

---

## 0. 硬约束

- **BRAM 新增必须为 0**（全工程只剩 3 块）。帧数据流经 **SDRAM**，不落 BRAM 帧缓存。
- 复位 `rst` **高有效**；`vs/de` 与像素同拍。
- 复用现有 **SD 读 + SDRAM 写**通路，**不重写** FAT32/CMD/CRC 层，只在"数据喂给 SDRAM 的方式"上改。

## 2. 核心思路：绕过 BMP 解析，直接流原始帧

BMP 每帧要解析文件头/像素，慢。**预先把帧转成"原始 RGB 流"存在 TF 卡**，FPGA 只做"连续读出 → 灌 SDRAM → 显示"：

- 帧格式：`640×480×RGB888`（每帧 921600 字节）或 `RGB565`（每帧 614400 字节，省 1/3 带宽）。
- 用一个 Python 脚本（离线，PC 上跑）把图片序列/视频抽帧成这个原始格式 + 一个**索引文件**（每帧偏移/长度）。
- FPGA 侧：按 `24fps`（≈ 每 1/24 秒切一帧）连续从 SD 读下一帧、写进 SDRAM 的**双缓冲**，
  显示端在两块缓冲间翻转（**乒乓 buffer**，避免半帧撕裂）。

### 关键点

1. **双缓冲（乒乓）**：SDRAM 里留 2 块帧缓冲，显示读 A 时后台写 B，写完翻转。这是"视频不撕裂"的核心。
2. **带宽核算**：RGB565 640×480@24fps ≈ **14.7MB/s**；你 SD 4 位 50MHz 理论 ~25MB/s，够，但要确认
   **读 + 写 SDRAM 并发**够不够，必要时降到 RGB565 或 20fps。
3. **连续簇**：帧文件在 TF 卡上连续存放，FAT32 一次解析簇链后**顺序读**，不要每帧都重走目录/簇链。

## 3. 分两个里程碑

### 里程碑 A：离线造帧 + 静态连播（先 2 帧乒乓跑通）

- 写 `scripts/make_raw_video.py`：输入图片序列，输出 `video.raw` + `video.idx`。
- 改 FPGA：把"换图节拍"改成 24fps 定时翻转双缓冲；先只验证 2 帧来回翻，确认无撕裂、无错位。

### 里程碑 B：连续流（多帧 + 实时读 SD）

- 增加"边显示边预读下一帧"：显示帧 N 时后台把帧 N+1 灌进空闲缓冲。
- 加**欠载保护**：SD 读慢了就重复显示当前帧（丢帧不掉帧错位），别黑屏/花屏。

## 4. 验证（必须全绿）

1. `sim/tb_raw_video.v`：模拟 SD 供数 + SDRAM 乒乓，断言帧切换时刻、无半帧撕裂、欠载时正确重复帧。
2. 离线脚本自检：`python scripts/make_raw_video.py --selfcheck`（帧尺寸/字节数/索引一致性）。
3. `python scripts/static_check.py` **ALL PASS**；新源文件登记进 `video_improve.al`（两份）与
   `scripts/design_files.txt`。
4. ModelSim 回归新增 tb **PASS**；TD 综合全绿。
5. 实机验收：连续播 10 秒不花屏不黑屏，帧率目测 ≥ 20fps。

## 5. 资源预期（验收线）

- LUT：双缓冲翻转 + 预读状态机 ≈ **400~600 LUT**；BRAM **新增 0**（帧在 SDRAM）。
- 关键成功标准：**帧数据全程走 SDRAM，BRAM 不涨**；实机能连续播放不撕裂。
