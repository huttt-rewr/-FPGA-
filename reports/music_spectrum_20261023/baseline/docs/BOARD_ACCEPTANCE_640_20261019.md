## 1. 使用哪一个 bit

使用 [hdmi_640_plain_800_audio.bit](../reports/board_accept_20261019/candidate/hdmi_640_plain_800_audio.bit)。不要选择根 reports 中早期的 bit，也不要拿只改了 RTL 却没重新生成的 bit 测试。

| 项目 | 候选文件对应值 |
|---|---|
| 器件 | Anlogic EG4S20BG256，工具报告速度等级 NA |
| 字节数 | 635,444 |
| SHA-256 | `c4981724248155ccba2226994ec3d1a9d7a6a118175ec2f7c48d6bf89c22646d` |
| SWNS / STNS | +0.044ns / 0 |
| HWNS / HTNS | +0.024ns / 0 |
| 资源 | 15,785 LUT、41 BRAM、23 DSP、10,158 REG |
| 已有回归 | 101 项 ModelSim 全通过；本次未改 RTL，未重新跑相同的 101 项 |

独立 TD 会话读取已验证的布线数据库，生成 bit **之前、之后**都重新报告 STA，四项数值与原构建一致，两个模式的像素/串行时钟仍在。没有重新布局或改变约束。文件与原数据库/源清单的绑定见 [candidate/manifest.json](../reports/board_accept_20261019/candidate/manifest.json)。

本候选是待实板验收版本。既有 SDRAM 位置和局部时钟布线警告仍未签核，SD/DDC/TMDS 外部 IO 仍需板级验证，内部正裕量不等于外部电气通过，也未达到整体 +0.5ns。

## 2. 准备设备与 TF 卡

使用现有开发板、下载器、FAT32 TF 卡、显示器和原有 PS/2 键盘。800 模式切换需要已有 R 键；KEY/SW 没有新增分辨率切换功能。两种显示器能力测试可以分两次完成；没有相应显示器时，对应 EDID 项记“未测”，不要记通过。

1. 显示器连接开发板 **HDMI_B / HDMIB**，选择对应 HDMI 输入。HDMI_A 不参与本工程。
2. 下载器、电源、PS/2 接口按现有板卡接法连接；详细接口说明见 [接线教程](CONNECTION_AND_USAGE.md)。
3. 从 [sd_files](../reports/board_accept_20261019/sd_files/) 取出下面 **7 份 BMP 与 1 份 WAV**，用电脑资源管理器复制到 FAT32 卡根目录。只复制这些普通媒体文件，不要把整个目录当作子目录复制，也不需要写裸镜像。
4. 若卡原来有其他 BMP/WAV，它们会影响枚举位置；记录本次卡内文件，按 OSD 图像实际内容识别，不要假设文件名排序就是数字键序号。
5. 安全弹出 TF 卡，再插回板上卡座。显示器先开机并选好输入，随后配置 FPGA。

| 文件 | 分辨率 / 内容 | 用来观察什么 |
|---|---|---|
| `RED.bmp` | 640×480，纯红 | 是否红蓝互换、噪点、白条 |
| `GREEN.bmp` | 640×480，纯绿 | 绿色通道与噪点 |
| `BLUE.bmp` | 640×480，纯蓝 | 蓝色通道与噪点 |
| `GRID640.bmp` | 640×480，1 像素外框、4 像素内框、网格、角标、RGB 色条与灰阶 | 实际 640 输出时检查边缘、位置、几何和灰阶 |
| `GRID800.bmp` | 800×600，同类图案 | 实际 800 输出时检查边缘、位置与颜色 |
| `SMALL.bmp` | 320×240 | 放大是否保持比例、是否仍完整显示 |
| `PORTRAIT.bmp` | 360×640 | 竖图比例、居中及左右补黑 |
| `TONE.wav` | 48kHz / 16bit / 单声道，6 秒 | 440Hz 两秒 → 静音一秒 → 880Hz 两秒 → 静音一秒 |

预览见 [media_preview.png](../reports/board_accept_20261019/media_preview.png)。文件格式、长度和 SHA-256 均经现有 BMP/WAV 校验工具核验，[清单在这里](../reports/board_accept_20261019/media_manifest.json)。测试音做了渐入/渐出，先把显示器音量调低，再逐渐调到可听。

## 3. 配置候选

在 TD 配套下载工具里连接已有下载器、识别器件链，核对器件是工程对应的 EG4S20BG256，再选择本页第 1 节的 bit 做 **JTAG 临时配置到 FPGA SRAM**。不同下载器的菜单名称可能不同；以其文档为准。本轮没有执行远程下载、擦除或写配置 Flash。

Windows 可在配置前校验候选：

```powershell
Get-FileHash E:\fpga\reports\board_accept_20261019\candidate\hdmi_640_plain_800_audio.bit -Algorithm SHA256
python E:\fpga\reports\board_accept_20261019\prepare.py verify
```

临时配置断电后通常需要重新配置。用户复位按钮只复位逻辑，与重新下载 bit、写 Flash 是不同操作。

## 4. 第一项：640 静态图、颜色和叠加

1. 配置完成后默认请求 VGA。等待首图完整装载，OSD 箭头后实际输出应为 **640×480**。本工程像素时钟为 25MHz，刷新约 59.524Hz，显示器菜单显示约 60Hz 正常。
2. 若 KEY 菜单未关闭，长按 KEY3 约 1.1 秒退出；短按 KEY3 到 `MODE:PLAY`。用 KEY1 或键盘左右键逐张选择图片，轮播先保持 OFF。
3. 先开 OSD 记录输出尺寸，再按 O 关状态层，并把字幕相关 SW 关闭，使纯色底图便于观察。依次看红、绿、蓝，确认没有串色、闪点、小白条；重新打开 OSD 检查文字。
4. 选 `GRID640.bmp`。显示器若有“保持比例/1:1/关闭过扫描”选项，记录实际选择。四个角标、白色外框和黄色内框应在应有位置；不要把显示器自身缩放或过扫描裁切直接判定为 FPGA 相位错误。
5. 检查 `SMALL.bmp` 与 `PORTRAIT.bmp`：内容完整、比例正确，竖图居中补黑。非匹配分辨率素材经过双线性缩放，不能用它的单像素边框证明输出没有一像素偏移。
6. 再启用字幕与滚动；切原有 SW 特效和转场，按 O 检查状态 OSD/玻璃/波形开关；按 G 进入游戏、方向键移动、G 退出。确认原图与各层相对位置正确。

640 不发送 HDMI 音频，静音是本轮确定的模式差异。`A:R` 只表示内部 WAV/PCM 状态；不能凭它判断 HDMI 在发声，也不能将静音判为 640 核故障。

填写 [BOARD_RESULTS.md](../reports/board_accept_20261019/BOARD_RESULTS.md) 的第一项，记录显示器型号、图像现象与相关素材。

## 5. 第二项：800 图像与 WAV 声音

1. 确认游戏已退出，按一次 R 请求 800。松开按键，等屏幕暂黑、重新锁定、重新挂载和装载完成。
2. **看箭头后实际输出必须是 800×600**；单独看到 `R:2` 不算。回退成 640 时不能验证 800 音频。
3. 选择 `GRID800.bmp`，重复检查颜色、边框和 OSD。实际刷新约 60.317Hz。
4. 若卡里只有 `TONE.wav`，它是唯一音频；A 松开后两秒内按 0 可重新选择。音量初始 08，确认 M/KEY 菜单未静音、音量非零、显示器本身有扬声器或音频输出且未静音。
5. 听 440Hz → 静音 → 880Hz → 静音的顺序，观察无持续杂音、断续或爆音。文件会按现有播放器逻辑循环，文件循环边界要与读卡故障区分。
6. 有声音时同时观察静态图，翻图、切字幕/转场和音量调节，再看是否引入白条、撕裂或 `U1`。如出现，记录当时所有状态，不能直接归因于 TMDS 编码。

默认 640 本身没有声音；只有回退 640 的显示器不能完成本项。没有听到声音时，先区分“模式不对 / 格式错 / 静音 / 音量 / 显示器无扬声器 / 读卡错误”，不要先修改音频 RTL。

## 6. 第三项：EDID 两类显示器

EDID 只在启动读取。更换显示器要连接好之后重新配置或全局复位，单纯插拔后按 R 不会触发重新读取。

| 条件 | 操作 | 通过现象 |
|---|---|---|
| 已知 EDID 支持 800×600@60 | 启动默认640，按R请求800 | 实际输出800×600，显示器锁定 |
| 已知 EDID 只支持640、未列出800×600@60 | 同样启动后按R请求800 | 请求R:2，但实际仍640×480，画面正常 |

显示器面板原生 1920×1080 不表示它不支持 800；桌面系统当前设置为 640 也不能证明 EDID “只支持640”。记录型号及能取得的 EDID 能力证据。没有第二类显示器或已配置好的 EDID 测试设备时，本项保留“未测”，逻辑级的 `tb_edid_i2c` 不替代这次实板结果。

DDC 实现的 SCL 仍为原 output 接口，只拉低或释放，不能检测从机时钟拉伸；若某显示器 EDID 失败，记录设备和总线波形。预期 SCL 约 99.206kHz，事务为 A0、偏移00、重复START、A1、128字节、STOP。NACK 及超时会安全回退，但“安全回退”不等于该显示器 EDID 读取已通过。

## 7. 第四项：模式切换与复位

在支持800的显示器上，每次按R后都等待稳定：

```text
默认 R:1 / 640
  → R:2 / 800
  → R:0 / 640
  → R:1 / 640
```

至少记录 10 轮完整循环。确认每次重新锁定、首图完整、没有永久花屏/黑屏/卡死；800 的声音恢复，640 没有 HDMI 音频。切模式暂停原轮播，需再按空格/KEY2 开启，不当作故障。再按全局复位，确认回到默认640、图像与 OSD 恢复。

记录每次重锁大致耗时、卡/显示器、是否出现数码管重启计数变化或 OSD 错误。通过这四项是功能门禁，不等于外部 IO、电气与长时间可靠性全部签核。

## 8. 出问题怎么定位

先固定一个素材、一个模式、关闭轮播，记录 bit 哈希和现象。**不要同时修改极性、相位、位序和时钟。**

| 现象 | 先检查 |
|---|---|
| 两档都无图 | 候选是否确实下载、HDMI_B/显示器输入、板卡复位与SD/SDRAM诊断 |
| 只有640无图而800正常 | 输入VS/DE周期、控制码、串行位序/时钟关系及显示器锁定；再依据测量决定是否实验性调整极性 |
| 640左右差一像素 | 先排除显示器缩放/过扫描，用GRID640复现；再核对VS下降沿与恢复HS相位 |
| 颜色交换 | 用纯色确认通道映射；红蓝互换与十位符号位序错误是不同问题 |
| 800不出声 | 实际尺寸、音量/静音/显示器能力、WAV格式、A:E1..E4、U1 |
| 请求800却留在640 | EDID能力/读取失败/超时；按既有回退逻辑区分 |
| 静态图白条/撕裂 | 记录是否与翻图/音频有关，检查帧缓存诊断和读卡/内存状态；不能凭现象归结为同步极性 |

当前源码基线：blue 控制码输入 `{vs,hs}`，HS/VS 低有效；复位 `h=0`，`frame_start` 这拍消费(0,0)，下一拍计数 `h<=1`。最终实板采用值留在验收表中，**现在尚无实物确认**。翻转同步极性不保证一定修复无图，改变 `h<=1` 也不能绕过相位核对。需要试验时，独立候选、单点修改、重新仿真和构建，并重新记录 bit 哈希。

## 9. 后续功能何时开始

四项实板结果齐全并通过后，按本次任务书 A→B→C 推进。每一步保留当前可回退 bit、原图声与全部叠加功能，静态/新增单测/全量回归/完整 STA 都通过才继续；SWNS 不得低于 +0.044ns、STNS 保持0、无新增 CRITICAL。

“放在25/40MHz像素域”不能预先保证全局 STA 不受影响，新增逻辑仍会改变布线。降低目标换图 FPS 只会减轻运行时读卡/装载负荷，**不会自动修复固定100MHz时钟的 setup 违例**；若 STA 变负，仍需真实的RTL/物理优化或按任务书回退。
