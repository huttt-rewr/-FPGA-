## 仍需改进：优先级高

### 1. 完成时序和板级签核

内部 removal 仅 3 ps，余量很小。应向 IP 提供方核对复位复制/同步网络、受支持实现方案和目标速度角，再对实际路径优化并重跑 final STA。TD Speed=NA 不证明已按实物 I7 角验证。不能用普通输出延迟去修复内部复位路径。

check_timing 报告：no clock=0、invalid constraint=0、combinational loops=0、no path constraints=0，但 no input delay=7、no output delay=24、abnormal input delay=32、dummy node 分类数=3。dummy node 下实际列出多个物理节点，不是只有三根未连接 RTL 线。这些提示不能统称零警告或全部已约束。

PHY-7002 两条 SDRAM 位置未满足、PHY-5079 一条局部时钟仍存在。局部网络为 sys_pll_m0/pll_inst.clkc[2] → U3/u2_ram/SDRAM_CLK。需安路核对合封宏映射/位置和时钟资源；当前没有依据直接删宏或改固定位置。USR-6135、PHY-5014 本轮没有出现，不能继续列成当前警告。

外部 SD、DDC、TMDS 需按器件和 PCB 数据约束/测量。HDMI 原理图、电阻、接收终端、共模、眼图和显示器兼容性尚未确认。

### 2. SDRAM 接口契约与集成回归不足

frame_fifo_read.v:81 用固定 10 个空闲周期判断读突发排空，未用 Sdr_rd_en 计数确认返回；读写调度器未使用输入 Sdr_busy/Sdr_init_ref_vld。FIFO 满/空输出在 frame_read_write.v 未接到错误监测。是否会在刷新或控制器停顿中丢数据，取决于加密核接受请求、排队及返回延迟契约，目前没有带官方核的证据，不能直接断定必然丢数据，也不能声称已验证安全。

建议先取得控制器契约，再加入刷新、读返回延迟、读写竞争、FIFO 满/空与连续多帧测试，必要时使用接受/返回计数和欠载错误。现有模型测试不能替代这些验证。读 FIFO 仅由 read_fifo_aclr 清除，系统复位后到首个帧请求前的行为也应纳入集成测试。

### 3. SD 初始化/扫描和换帧等待缺少完整恢复

sd_card_cmd.v:201 等待数据 token 没有超时；初始化命令反复重试、扫描读卡时上层不处于 load_busy，约 5 秒加载看门狗不覆盖它们。无卡、拔卡或永久无响应时可一直卡住。sd_card_bmp.v:272 的超时又排除了 commit_wait，视频提交确认丢失会一直忙。

建议分开设置初始化、命令响应、数据 token、扫描和提交看门狗，报告具体错误/重试次数，保留已显示帧。提交超时不能简单翻回 toggle，应设计可确认的取消/重新同步协议，避免迟到确认破坏缓冲区所有权。

## 仍需改进：功能健壮性

建议下一阶段先完成 SDRAM/SD 异常集成测试与错误状态，再推进官方 IP/板级时序确认，最后扩展文件系统和分辨率。不会把本轮目录整理和模块回归等同于完成整个播放器硬件验收。
