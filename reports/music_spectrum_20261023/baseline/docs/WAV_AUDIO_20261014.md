## 1. 接线和支持范围

显示器接开发板 **HDMI_B / HDMIB**，声音和图像共用一根HDMI线。显示器需支持HDMI音频，并有扬声器或其自身音频输出。先选对显示器输入、解除显示器静音并调低音量。HDMI转DVI或无扬声器屏幕不能用于判断出声。

TF卡插原有卡槽。控制仍只用KEY/SW，无需UART、DAC、I²S或新管脚；官方HDMI核、PHY、PLL、SDRAM及FIFO IP保留。

| 项目 | 范围 |
|---|---|
| 格式 | 小端RIFF/WAVE，PCM format=1 |
| 采样率/位深/声道 | 48000Hz / 16bit有符号 / mono |
| 一致性 | byte_rate=96000，block_align=2 |
| 长度 | 头和数据合计≤16MiB；标准头最多约174.76秒PCM |
| 存储 | FAT32根目录第一个WAV；支持碎片簇链 |
| 播放 | 单段循环，左右输出相同PCM |
| 头解析 | 遍历fmt/data及未知块，支持奇数padding、跨扇区头；fmt在data前 |

不支持MP3、AAC、FLAC、浮点WAV、WAVE extensible、立体声直接播放、音频列表或FFT。16bit PCM扩展为24bit接口数据不增加原始精度。

## 2. KEY怎样开声、调音量

复位默认 **MUTE=ON，VOLUME=08**。默认不读WAV，只放图片的卡仍可演示。

1. 先确认图片稳定。长按 **KEY3约1.1秒**并松开，打开菜单。
2. 复位后菜单从PLAY/PAUSE开始，按 **KEY2四次**到AUDIO MUTE。曾移动菜单时按KEY1向上、KEY2向下找到此项。
3. 短按 **KEY3并松开**，AUDIO MUTE:ON变为OFF，开始读头、预填FIFO。
4. 长按KEY3退出。右侧 **A:R- V:08 U0** 表示格式已接受且无保留的失败记录；不能证明显示器已出声。
5. 菜单 **VOLUME DOWN**：每次短按KEY3减1，到0停止；**VOLUME UP**：每次短按KEY3加1，到31停止。
6. 要暂停声音，在AUDIO MUTE短按KEY3切回ON，再长按退出。

菜单顺序：PLAY/PAUSE→GAMMA→DIAG→DIAG PAGE→AUDIO MUTE→VOLUME DOWN→VOLUME UP→首项。KEY1反向、KEY2正向，KEY3确认。KEY1/2在音量项仍是导航，不是直接加减；没有长按连发。长按KEY3不会同时切换普通MODE或确认。

| OSD | 含义 |
|---|---|
| A:M | 静音，PCM读取/播放暂停、队列保留 |
| A:- | 头尚未准备；等SD初始化与读头 |
| A:R | 头已接受；不证明永不欠载或实物出声 |
| A:E1..E4 | 保留的失败原因：头/格式、SD读错/超时、扇区长度、chunk结构；失败后一秒自动重试，真实PCM输出后清除 |
| U0 / U1 | 是否曾音频欠载；U1恢复播放后仍保持，整机复位清除 |
| V:00..31 | 逻辑音量，复位回08 |

音量0只将幅度置0，PCM进度继续；MUTE暂停进度，恢复后先播放已有队列。**PLAY/PAUSE只控制图片轮播**。SW四路仍为字幕、滚动、转场低位和高位，没有改成音频开关。

KEY1/2/3对应FPGA管脚B2/C1/B1，整机复位为A2。这是封装坐标，不能直接代替实物丝印；详见 [KEY/SW教程](KEY_SW_OPERATION.md)。断电/复位不保留音频设置。

## 3. 准备FAT32卡

本轮直接把BMP和WAV复制到FAT32根目录，不使用旧镜像pack/烧卡流程。用下面命令生成或转换符合要求的普通WAV，然后在资源管理器中复制到卡：

```powershell
python scripts/prepare_audio.py tone media/SOUND.wav --seconds 3 --hz 440
python scripts/prepare_audio.py check media/SOUND.wav
```

已有其他WAV可用`python scripts/prepare_audio.py convert input.wav media/SOUND.wav`转换。完整文件名、目录和卡格式要求见[FAT32教程](FAT32_USAGE_20261015.md)。旧裸镜像候选不支持普通文件拷贝，需使用本轮重新构建的配置。

## 4. 数据链路与保护

    原SD SPI栈 → sd_read_arbiter（扇区级锁定所有者）
                     ├─ BMP扫描/缩放 → 原图片双缓冲
                     └─ audio_wav（512字节CRC成功扇区缓存）
                              ↓ 16bit小端PCM符号扩展
                         audio_async_fifo（1024×24）
                              ↓ 100MHz→25/40MHz
                         audio_playback（48kHz、增益、饱和）
                              ↓
                         原HDMI音频/ACR接口 → HDMI_B

音频只有实际请求扇区时才优先，授权后地址和所有者保持到end/error，结束留两个空拍。FIFO占用≤764且未满时才推进音频，预留至少260个样本空间；一扇区最多256样本。图片等待仲裁不计作已授权扇区停滞；读卡超时中止并复位底层。

解析器把RIFF合法性、块剩余空间、含padding长度和分支应用拆到独立寄存阶段，仲裁器提前寄存超时译码且保持原到期拍数；避免100MHz组合长路径。监督器直接输出高有效复位寄存器，去除ready取反/OR级联，仍异步断言、同步撤销。最后以真实P&R报告验收，未新增时序屏蔽。

音频必须收到完整512字节和CRC成功end后才解析。坏扇区不泄漏新样本；音频失败清空音频队列，不直接把格式错误记成图片LOAD错误。底层重新初始化仍可能影响图片加载。

FIFO二进制寻址、格雷码两拍跨域同步，RAM不复位，公共复位分别同步释放。1024样本约21.33ms；预填256样本约5.33ms播放数据。不能覆盖任意长的卡延迟；欠载送0并重新预填，可能听到停顿。

资源必须按报告评估：音频FIFO实际映射两块BRAM9K、WAV扇区缓存一块；解除固定静音后，两份官方HDMI核的音频包FIFO各从七块增至十一块，所以整机相比早先板载版增加十一块、共57/64（89.06%）。不是只加一两块。官方IP保持原样，后续扩展需重新评估余量；最终LUT/寄存器和STA见构建状态。

采样累加器每拍加48000，达到当前像素频率时减去频率并发事件。25MHz间隔520/521拍，40MHz间隔833/834拍，平均48kHz；同步FIFO读和乘法流水对齐。

ACR保持N=6144、25MHz CTS=25000、40MHz CTS=40000，Fs=F_TMDS×N/(128×CTS)=48000。F_TMDS是时钟通道频率。没有修改HDMI核或新增时钟域。

## 5. 音量与局限

使用任务书指数表 round(32768×2^(k/32))，16bit幅度对齐24bit后乘表、除65536并作有符号24bit饱和。0级特别静音，1..31约51.1%..97.9%，08约59.5%。这是较窄指数范围，不是0..100%连续音量，也不是每级1dB；更大范围用显示器调节。

没有静音/音量渐变斜坡，突变可能点击。图片正常换图与音频独立；加载中止、SD重新初始化、模式复位可清队列或重新读头，不保证无中断。没有保证所有卡/显示器组合出声。

## 7. 无声排查

1. 确认WAV版本候选、HDMI_B、显示器输入和音频能力；显示器先低音量。
2. AUDIO MUTE=OFF，VOLUME不为00。
3. A:E1..E4：按[错误码表](AUDIO_RETRY_20261014.md)排查，用 `prepare_audio.py check` 检查普通WAV文件，确认已直接复制到FAT32根目录，并使用匹配本版源码的配置。瞬时故障消失会自动重试；永久坏文件必须修正，更换卡内容后应复位重新挂载、枚举文件并解除静音。
4. A:-持续：查SD初始化、FAT32挂载和根目录是否有WAV；图片正常不证明根目录存在合规音频文件。
5. A:R仍无声：查显示器音量、HDMI音频支持和是否用了DVI适配，记录模式、卡型号、现象。
6. 间歇声音：区分卡延迟/欠载、加载中止、模式复位和接收端问题；A:R不能证明FIFO一直有数据。
