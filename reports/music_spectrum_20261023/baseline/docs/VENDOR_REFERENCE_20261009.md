## 2. 从基础理解：存储空间到底有多大

`bit`是单个二进制位，`byte`是8位；MiB按2的幂计算。EG4S20合封的EM638325为2M×32bit，容量是67,108,864bit，即 **8,388,608byte = 8MiB**。手册中的64Mb不是64MB。

| 本工程数据 | 计算 | 含义 |
|---|---|---|
| 一帧可见像素 | 640×480=307,200 | 不包含消隐期间的位置 |
| BMP像素负载 | 307,200×3=921,600字节 | B/G/R各8位；另有文件头 |
| SDRAM一帧 | 307,200×4=1,228,800字节 | 每字存`{R,G,B,8'b0}` |
| SDRAM两帧 | 2,457,600字节，约2.344MiB | 小于8MiB，容量足够；不证明时序或带宽足够 |
| 第二帧起点 | 307,200个32位字 | `BUF1_ADDR`是字地址，不是307,200字节 |
| SD图片扫描区 | 64MiB | SD卡扇区扫描边界；并非将64MiB全部搬到SDRAM |

手册PDF5标200MHz、800MB/s属于器件能力描述。当前内存时钟40MHz，32位总线原始上限按 `40M×4=160MB/s` 计算；初始化、刷新、读写切换、仲裁会占用时间，实际有效吞吐需测试。显示读带宽平均约 `1,228,800×59.524≈73.14MB/s`，可见区瞬时为 `25M×4=100MB/s`，加载时还要加写流量。FIFO用来吸收短期供需差，不能弥补长期带宽不足。

芯片还提供19,600 LUT、64块ERAM9K、16块32Kb RAM、29个18×18乘法器、4个PLL等资源。这是器件总量，项目实际占用应看当前 [物理资源报告](../reports/physical_area.txt)，不能把手册示例占用当本工程统计。

## 3. SDRAM手册给出了哪些新依据

对应资料：ZIP内 **APUG011_基于ERAM接口实现的高性能SDRAM读写v1.2.pdf**，APUG011_1.2 / 2023.06。

| 官方描述 | 本工程应如何理解/核查 |
|---|---|
| PDF6 §2.3：读写不能同时操作，开始前检查刷新结束 | 调度不只要避免同拍使能，还要覆盖上一事务在途返回与下一写事务的边界 |
| PDF7 §2.3.2及图2-5：请求后10拍开始输出有效读数据 | 当前固定10拍有参考依据；这是特定接口时序，不足以证明任意时钟/刷新场景下“末尾等10拍就一定安全” |
| PDF10表3-1：`Sdr_rd_en`标识有效返回 | 测试应统计真正返回的字，检查请求数、返回数、顺序及帧尾；不能只看请求计数 |
| PDF8：以4个32位字为一组，跳转在组边界 | 当前行长640、帧长307200和第二帧基址均4字对齐；通用尾部长度1/127等模块测试通过不等于官方控制器已支持对应事务 |
| PDF9：自动刷新计数依赖`global_def.v`时钟宏 | 当前宏是40MHz，周期25ns，刷新间隔整数计算为1250拍；示例150MHz不能直接照搬 |
| PDF6：持续写入要求SDRAM时钟64MHz以上 | 当前40MHz不能直接套用该连续写入保证。须验证现有有限突发、空闲和刷新调度，不能只凭降频认为更可靠 |
| PDF15第6条：不同频率/相位可能造成数据错一拍 | 结合PLL模型、最终时序和真实控制器验证；手册不能替代本板采样窗口测量 |

**手册有矛盾和示例边界。** PDF10将`Sdr_busy`描述为“忙状态，暂不使用”，PDF15又要求每次操作前判断它。PDF8跳转示例写`[22:2]`，表3-1接口则是21位地址；不能把文本示例直接粘进当前RTL。当前调度器的`Sdr_busy/Sdr_init_ref_vld`输入尚未参与控制，属于需要解决的接口契约问题，但不应未经核对就加一个`!busy`门控，导致丢请求或事务中途被切断。

建议分步骤处理：

1. 固定当前IP、PLL、40MHz宏和工程版本，取得这套控制器的“何时接受请求、如何安排刷新”的准确说明。对手册矛盾向厂商确认。
2. 用匹配的控制器仿真或受支持的模型记录初始化、刷新、读写使能、地址、返回有效及数据；覆盖刷新前后、读写切换、整帧末尾、行翻转、加载失败复位。
3. 以请求/返回记分板判定数据完整，核查FIFO余量包括在途返回。若采用返回计数完成机制，要先定义接受事件、复位和错误退出规则，避免等待根本未被接受的请求。
4. 验证现有有限写突发在40MHz下是否满足保持刷新和吞吐要求，再决定是否改变仲裁或频率。改变频率还须更新PLL、刷新宏、约束、回归和实现结果。
5. 上板做地址模式、固定图案、随机数据和长时间静态保留测试，配合可观测错误计数；不能用“偶尔出图”代替内存验收。

APUG010是 **8位异步Local Bus** 接口方案，地址、握手、字节掩码转换与当前32位App接口不同。可以参考其独立内存测试思路，但不能把它当当前`sdram.v`的直接替换文件。

## 5. HDMI：数字协议与电气输出分开理解

APUG092 DOCX §2.2规定串行时钟为像素时钟5倍；配合DDR在上升沿和下降沿各发一位，形成每像素10bit。本工程25MHz/125MHz对应每个数据通道250Mbit/s。ODDR原语可查HDL库PDF23–24；它负责双沿输出，不负责BMP解析或EDID模式选择。

§2.4.2要求**一行有效数据连续**，ready只在行末之后拉低。当前每行必须送640个像素，`user`在帧首，`last`在行末。普通AXIS允许任意停顿的抽象不能替代此核约束；64像素队列也不能吸收无限背压。`O_video_locked`可作为后续诊断候选，但当前未接入用户可见状态。

§2.4.1的EDID读事务输出128字节；当前只检查基础块头和校验和，不自动协商分辨率。§2.4.3/2.4.4分别是音频样本和ACR输入。当前PCM测试音与N/CTS已接入，不等于支持SD音频文件或外部I2S。手册§5把Test bench/Simulation/IP Model列为N/A，因此不能宣称该包已经提供能直接运行的完整HDMI仿真环境。

IO手册PDF9表4-2-2确实列出 **Rs=150Ω、Rp=140Ω、LVDSE33幅度483mV**；PDF10注明 **8mA驱动、接收端100Ω差分终端**。图4-2-4的拓扑是两根输出各串一个Rs，串联之后两线间跨接Rp，接收端另有100Ω。

这纠正了旧文档“只有用户提供数值、未取得IO手册”的资料状态，但**不能推导出本板应加150/150/140Ω或HDMI已合规**：表格面向LVDS，而TMDS终端与共模条件不同。需核对现有板上网络、接收端负载、输出电流、幅度、共模及眼图。8mA属性是驱动设置，不表示任意负载下恒定输出8mA。

## 6. BG256引脚与供电：哪些已证实

数据手册PDF16–21 §6.4属于 **EG4S20BG256**。PDF18再次确认HDMI所用Bank3配对：C3/C2、G5/G6、F1/F2、E1/D1。PDF21顶部注释明确：**VCCIO1、VCCIO3、VCCAUX内部相连，VCCO1/VCCO3只能接3.3V**。这不是让使用者给整板电源口输入3.3V，而是芯片供电和改板设计约束。

## 7. PLL、FIFO及常见名词

PLL手册PDF2给出输入10–500MHz、VCO300–1200MHz范围。当前50MHz×20/1=1000MHz在此范围，输出分频形成100/40/40和25/125MHz。PDF3的No Compensation采用内部反馈，不补偿时钟网络；不能解释成“零插入延迟”。PDF4–5细相位步长为VCO周期的1/8，1GHz下是125ps，不能写成固定150ps。

手册PDF8建议输入稳定后复位PLL并关注锁定。当前PLL复位端固定为0，用户逻辑通过锁定条件复位；官方模型测试通过，但硬件上电、掉锁恢复、模拟环路配置仍需复核。软件手工补丁不能改写成“已由TD向导重新生成”。

Soft FIFO手册PDF6–11区分普通读、输出寄存器、show-ahead及不同复位模式。普通读是请求后返回数据；show-ahead会提前把首字摆在输出。当前FIFO为旧生成接口，不能把新版手册的复位拍数、valid延迟、实际容量和端口名逐项照搬。应按当前RTL参数、内部逻辑和测试波形核对。PDF17–18还说明新版生成的CDC约束不能被全域异步/false-path覆盖；同样不能假定本工程旧FIFO自动拥有新版IPC约束。

| 名词 | 在本工程中的含义 |
|---|---|
| `.adc`约束文件 | TD物理/管脚约束，和模拟ADC模块不是一回事 |
| `.sdc`约束文件 | 时钟和路径时序关系，不能通过改后缀代替物理约束 |
| `.v` / `.enc.v` | 可读RTL / 厂商加密RTL，二者都可能是必需设计源 |
| `.ipc` | IP配置及工具关联信息，不是图片文件 |
| `.al` | TD工程入口，登记器件、源文件与约束 |
| `.bit` | FPGA配置数据，描述加载后形成的电路 |
| `.bmp` / `.img` | 单张图片 / 本工程原始扇区图片镜像；不能作为FPGA配置位流 |
| ERAM / FIFO / SDRAM | 片上存储资源 / 顺序读写缓冲结构 / 需要刷新、容量更大的合封存储器 |
| setup / hold / removal | 数据建立 / 数据保持 / 异步控制释放相关检查；必须读报告类型和端点区分 |

## 8. 如何利用这些资料继续改进

建议先读接线教程完成正确使用，再读README数据流和模块表，然后按下面顺序处理问题：

1. **最先补SDRAM接口证据。** 重点是40MHz有限突发、刷新准入、真实读返回和帧切换。先做可复现模型/波形，再改调度器。
2. **增加诊断可见性。** 把已有FIFO溢出/欠读统计及HDMI视频锁定状态设计成可读诊断，再验证CDC与复位；当前OSD不能提供这些完整信息。
3. **复核PLL、封装映射和实现警告。** 让TD配置、官方模型、最终时序及厂商对PHY-7002/5079的解释互相吻合。
4. **拿到对应板卡原理图和器件速度等级。** 补SD/DDC板级时序依据，确认HDMI电气和USB/JTAG/UART接口，不填写臆测值消除警告。
5. **最后开展功能扩展。** DSP滤波、ADC采集、I2S和多启动都是独立新功能，需顶层接入、协议/时钟/资源规划和测试；当前应先稳定640×480链路。
